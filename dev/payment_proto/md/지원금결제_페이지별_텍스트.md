# 지원금 / 주문·결제 관련 페이지 텍스트 정리

> 출처: `B2B 기업 독서 프로그램 운영 관련 개발 검토사항_20260911.docx`
> 원문에 명시된 내용만 페이지 단위로 재정리함 (임의 추가 없음)

## 핵심 Flow (원문 그대로)

> "B2B 기업 임직원이 로그인 → 추천도서 또는 개인도서 선택 → 지원금 자동 적용 → 직원부담금 결제 → 배송/전자책 제공 → 서평 작성 → 회사 정산자료 자동 생성"

이 중 **지원금**과 **주문/결제**에 해당하는 구간은 다음과 같습니다.

```
독서프로그램 선택(추천/개인도서)
        ↓
   지원금 자동 계산
        ↓
 ┌──────┴──────┐
 ▼             ▼
회사지원금    직원부담금
 └──────┬──────┘
        ▼
    주문/결제
```

문서 14번 "개발 산출물" 중 Phase 2 UX/UI 화면 목록에서 이 구간에 해당하는 페이지는:
**도서상세 → 장바구니 → 결제 → 주문완료 → (마이페이지 내) 나의 지원금 / 나의 도서**

---

## Page 1. 도서상세 (지원금 자동 계산 노출 지점)

### 이 페이지가 가진 근거 (원문 §4, §5, §6)

**추천도서 화면 구성 요소 (원문 §4 "기능")**

- 도서정보
- 저자/출판사
- 도서소개
- 추천사유
- 구매하기
- 지원금 100% 자동 적용

**개인도서 화면 구성 요소 (원문 §5 "기능")**

- 종이책/전자책 구분
- 지원금 자동 계산

**지원금 표시값 — 추천도서 (원문 §3, §6.1: 지원금 = 판매금액 100%)**

| 판매금액 | 회사지원 | 직원부담 |
| -------- | -------- | -------- |
| 15,000   | 15,000   | 0        |
| 20,000   | 20,000   | 0        |
| 30,000   | 30,000   | 0        |

**지원금 표시값 — 개인도서 (원문 §3, §6.2: 회사 지원금 = MIN(판매금액 × 50%, 10,000원))**

| 도서가격 | B2B 기업 | 직원   |
| -------- | -------- | ------ |
| 10,000   | 5,000    | 5,000  |
| 16,000   | 8,000    | 8,000  |
| 18,000   | 9,000    | 9,000  |
| 20,000   | 10,000   | 10,000 |
| 30,000   | 10,000   | 20,000 |
| 40,000   | 10,000   | 30,000 |

**업무 Rule — 추천도서 (원문 §4 "업무 Rule", 순서 그대로)**

```
추천도서 선택
  ↓
월 1권 구매 가능 여부 확인
  ↓
구매 가능
  ↓
회사 100% 지원
  ↓
직원 결제 0원
```

### 페이지 텍스트 요소 (원문 근거 있는 것만)

- 도서 정보(도서명/저자/출판사/도서소개 — 추천도서는 추천사유 포함)
- 도서 유형 구분 표시: 추천도서 / 개인도서
- 개인도서인 경우: 종이책·전자책 선택 UI
- 지원금 자동 계산 결과: 회사지원 금액 / 직원부담 금액
- 월 1권 구매 가능 여부 확인 결과 (가능/불가)
- 구매하기 버튼 (추천도서) / 장바구니 담기(개인도서, 원문 §5에 장바구니 항목 존재)

> ⚠️ 원문에 "화면 안내 문구"(예: 배지 색상, 버튼 문구, 불가 시 안내 메시지 원문)는 없으므로 별도 창작하지 않음 — 기획 단계에서 확정 필요.

---

## Page 2. 장바구니

### 근거 (원문 §5 "기능")

- 장바구니 항목이 개인도서 시스템 기능으로 명시됨 (추천도서는 "구매하기"만 명시되어 장바구니 경유 여부 불명확 — **확인 필요 항목**)

### 페이지 텍스트 요소

- 선택 도서 목록
- 도서가격 / 회사지원금 / 직원부담금 (Page 1과 동일 계산 로직 적용)

> ⚠️ 원문에 장바구니 화면의 상세 구성(다중 선택, 합계 표시 방식 등)에 대한 서술은 없음 — Phase 2 "주요 화면" 목록에 "장바구니"가 명시되어 있을 뿐, 상세 사양은 미기재.

## Page 3. 결제 (복합결제 — 원문 §7 "복합결제 시스템")

### 원문 예시 그대로

> "예를 들어 25,000원짜리 도서를 구매하면"

```
도서금액             25,000원
B2B 기업 지원금       10,000원
직원 결제금액         15,000원
──────────────────────
최종 결제금액         15,000원
```

> "시스템상으로는 **회사 지원금 + 직원 결제금액**을 하나의 주문번호로 관리한다."

### 결제 프로세스 (원문 §7, 순서 그대로)

```
상품 선택
 ↓
지원금 자동 계산
 ↓
회사 지원금 차감
 ↓
직원 부담금 계산
 ↓
직원 결제
 ↓
주문 완료
```

### 페이지 텍스트 요소

- 도서금액 / B2B 기업 지원금 / 직원 결제금액 3단 표시
- 최종 결제금액(직원 실결제 금액) 강조
- 하나의 주문번호(Order ID)로 회사지원금+직원결제금 통합 관리됨을 표시
- 결제수단 선택 (직원 결제분에 한함 — 원문에 결제수단 종류는 명시 안 됨, **확인 필요**)

### 체크 필요 사항 (원문 §15 "③ PG 복합결제")

> "기존 영풍문고 PG 구조에서 지원 가능한지 확인 필요."

## Page 4. 주문완료

### 근거

Phase 2 주요 화면 목록에 "주문완료" 명시. 상세 구성 요소는 원문에 서술 없음.

### 연결되는 데이터 (원문 §7 "정산 데이터 구조" 필드 — 주문 시점에 함께 생성되는 값)

```
Employee ID     → 직원 식별번호
Order ID        → 주문번호
Book ISBN       → 도서 식별
Book Type       → 추천/개인
Format          → 종이/전자
List Price      → 정가
Selling Price   → 판매가
Company Subsidy → B2B 기업 부담
Employee Payment→ 직원 부담
Order Date      → 구매일
Refund Status   → 취소/환불
Review Status   → 서평 작성 여부
```

> ⚠️ 주문완료 페이지 자체의 화면 문구(완료 메시지, 배송예정 안내 문구 등)는 원문에 없음 — **확인/기획 필요**.

---

## Page 5. 마이페이지 — 나의 지원금 / 나의 구매내역

### 근거 (원문 §2 "① B2B 기업 전용 임직원 페이지" 메뉴 목록)

- 나의 구매내역
- 나의 지원금
- 독서현황

### 월 1권 통제 — 직원별 월간 지원금 Ledger (원문 §4, 표 그대로)

| 직원 | 월  | 추천도서 | 개인도서 | 지원금           | 직원부담 |
| ---- | --- | -------- | -------- | ---------------- | -------- |
| A    | 9월 | O        | X        | 18,000           | 0        |
| B    | 9월 | X        | O        | 10,000           | 12,000   |
| C    | 9월 | O        | O        | 정책에 따라 통제 | -        |

> "C" 케이스(추천+개인 동시 신청)는 원문에서도 "정책에 따라 통제"로만 명시 — **정책 확정 필요 항목** (요구사항\_정리.pdf 문의 회신에서도 "월, 분기, 반기 기준으로 검토" 중이라고만 답변됨, 확정 아님)

### 페이지 텍스트 요소

- 이번 달 추천도서 신청 여부(O/X) + 사용 지원금
- 이번 달 개인도서 신청 여부(O/X) + 사용 지원금 + 직원부담금
- 나의 구매내역 (주문 목록)
