# 모바일 웹/앱 디자인·코딩 표준 가이드라인

## 1. 디자인 표준

### 1.1 반응형 디자인
- **Viewport 설정**: `width=device-width, initial-scale=1.0` 필수
- **최소 너비 기준**:
  - 스마트폰: 320px ~ 480px (iOS/Android 모두)
  - 태블릿: 600px 이상
- **터치 타겟**: 최소 44×44px (iOS) / 48×48dp (Android) — 손가락 터치 편의성
- **간격(Spacing)**: 기본 단위 8px 기반 (8, 16, 24, 32, 40px…) 일관성 유지
- **텍스트 크기**: 최소 12px, 본문은 16px 이상 권장
- **줄 높이(Line height)**: 1.5배 이상 (가독성 확보)

### 1.2 네비게이션
- **Bottom Tab/Navigation Bar**: 4~5개 항목 권장 (6개 이상은 스크롤 필요)
- **Hamburger Menu**: 주요 기능은 하단 탭에, 보조 기능은 메뉴에
- **뒤로 가기**: 네이티브 앱은 시스템 버튼 활용, 웹은 명시적 버튼 제공
- **상태 표시**: 현재 페이지/탭 강조 (색상, 무게, 언더라인)

### 1.3 레이아웃
- **단일 컬럼 우선**: 모바일은 세로 스크롤 중심 (가로 스크롤 피하기)
- **최대 가독성 너비**: 너비 제한 없이 화면 전체 사용 (가로 여백은 최소 8px)
- **안전 영역(Safe Area)**: 노치, 둥근 모서리, 홈 인디케이터 고려
  - iOS: `safe-area-inset-*` CSS 변수 활용
  - Android: 시스템 바 높이 고려 (상단 25dp, 하단 48dp)

### 1.4 색상 및 명도
- **명도 대비**: WCAG AA 기준 최소 4.5:1 (텍스트) / 3:1 (UI 요소)
- **색상만으로 정보 전달 금지**: 반드시 다른 시각 단서 추가 (아이콘, 텍스트)
- **다크 모드 지원**: 흰색(#FFF) 배경만 제공하지 말 것 (배터리 소비, 접근성)
  - 배경: #121212 ~ #1E1E1E 권장 (완전 검은색 피하기)

### 1.5 타이포그래피
- **폰트 제한**: 웹은 2개 이상 피하기 (로딩 시간)
- **시스템 폰트 우선**: SF Pro Display (iOS) / Roboto (Android)
- **폰트 파일 크기**: WOFF2 포맷, 최대 50KB

## 2. 코딩 표준

### 2.1 성능
- **초기 로딩 시간**: 3초 이내 (3G 기준)
- **First Contentful Paint (FCP)**: 1.5초 이내
- **번들 크기**: 
  - 초기 JS: 100KB 이하 (gzip)
  - CSS: 50KB 이하 (gzip)
  - 이미지: 400KB 이하
- **이미지 최적화**:
  - WebP 포맷 우선 (JPEG/PNG 폴백)
  - 해상도별 제공 (`srcset` 활용)
  - Lazy loading 적용 (초기 로드 제외)
- **코드 분할(Code Splitting)**: 라우트별 또는 기능별 청크 분리
- **캐싱**:
  - 정적 자산: 1년 캐시 + 파일명 해싱
  - API 응답: 1분 ~ 1시간 (용도별 판단)

### 2.2 호환성
- **브라우저 지원 범위**:
  - iOS Safari 12+, Chrome 최신 2개 버전
  - Android Chrome 최신 2개 버전
  - 폴리필(Polyfill) 필요시 조건부 로딩
- **제스처 인식**:
  - `touch` 이벤트 (터치) + `pointer` 이벤트 (호환성)
  - 더블탭 줌 비활성화: `user-scalable=no` 또는 double-tap-zoom: none (CSS)
- **입력 방식**: 터치 + 키보드 + 음성 입력 모두 지원

### 2.3 접근성 (a11y)
- **HTML 시맨틱**: `<button>`, `<nav>`, `<main>` 등 의미있는 태그 사용
- **ARIA 라벨**: `aria-label`, `aria-describedby` 활용 (스크린 리더)
- **포커스 관리**: Tab 순서 논리적 구성, `:focus-visible` 스타일
- **컬러 대비**: 모든 텍스트 및 UI 요소 최소 4.5:1
- **텍스트 대체(Alt text)**: 의미있는 이미지는 설명 필수, 장식용은 `alt=""`
- **터치 크기**: 모든 인터랙티브 요소 최소 44×44px

### 2.4 네트워크 처리
- **오프라인 대응**: Service Worker로 기본 콘텐츠 캐싱
- **에러 처리**: 네트워크 에러/타임아웃 사용자 피드백 제공 (재시도 옵션 포함)
- **요청 최소화**: API 배칭, 불필요한 폴링 제거
- **타임아웃**: 요청 5초 이상 답 없으면 실패 처리

### 2.5 보안
- **HTTPS 필수**: 모든 요청 암호화
- **CSP(Content Security Policy)**: XSS 방지
- **입력 검증**: 클라이언트 + 서버 양쪽 필수
- **API 인증**: OAuth2 / JWT 토큰 기반
- **민감 데이터**: 로컬스토리지 피하기 (SessionStorage 또는 메모리 사용)

### 2.6 유지보수성
- **코드 구조**:
  - 컴포넌트별 폴더 분리
  - 설정 파일 중앙화 (색상, 간격, 크기 상수)
  - 유틸리티 함수 분리
- **네이밍 컨벤션**:
  - 변수/함수: camelCase
  - 클래스/컴포넌트: PascalCase
  - CSS 클래스: kebab-case
  - 상수: UPPER_SNAKE_CASE
- **주석**: 왜(Why)를 중심으로 (What은 코드가 말함)
- **버전 관리**: Semantic Versioning (MAJOR.MINOR.PATCH)

## 3. 공통 원칙

### 3.1 사용자 경험
- **피드백 즉시성**: 1초 이내 응답 (로딩바, 토스트, 스켈레톤 UI)
- **제스처 일관성**: 
  - 스와이프: 좌우 네비게이션
  - 핀치: 줌 인/아웃
  - 롱탭: 메뉴/선택 옵션
- **에러 메시지**: 구체적 + 해결 방법 제시 ("로그인 실패했습니다" ✗ → "비밀번호가 틀렸습니다. 초기화하시겠어요?" ✓)
- **스크롤 성능**: Passive event listeners, `will-change` CSS 최소화

### 3.2 테스트 기준
- **디바이스 테스트**: 최소 iOS 1종(iPhone 최신) + Android 1종(Samsung 또는 Pixel)
- **브라우저 테스트**: Chrome, Safari, Firefox 최신 버전
- **네트워크 시뮬레이션**: 3G(느린 네트워크) 환경 테스트 필수
- **터치 테스트**: 마우스만으로 테스트하지 말 것 (터치 스크린 사용)
- **보조 기술**: 스크린 리더(NVDA, JAWS) 테스트

### 3.3 배포 및 모니터링
- **버전 관리**: 앱 > 웹 순서로 버전 올리기 (앱은 심사 시간 필요)
- **무중단 배포**: Blue-Green 또는 Canary 배포
- **에러 모니터링**: Sentry, LogRocket 등으로 사용자 세션 캡처
- **분석 추적**: 
  - 화면 이동 경로
  - 주요 기능 사용률
  - 오류율 및 성능 지표
- **하위 호환성**: 낮은 버전 사용자도 기본 기능 동작해야 함
